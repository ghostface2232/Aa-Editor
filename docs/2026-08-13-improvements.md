# Noten 개선 방향 — 제품·UX·디자인·기획 (2026-08-13)

코드(src/, src-tauri/), 문서(README, AGENTS.md, docs/), 최근 커밋 ~60개를 기반으로 한 개선 제안입니다.
버그·결함 수정 항목은 [2026-08-13-bugs-and-issues.md](2026-08-13-bugs-and-issues.md) 참조.

## 현재 위치 요약

- **포지셔닝**: 검증 가능한 로컬 퍼스트("노트가 디스크를 떠나지 않는다") — HTTP 플러그인 없음, fs 스코프 제한, 클라우드 드라이브 폴더를 통한 수동 동기화 + `.conflicts/` 백업. Obsidian Sync/Notion 대비 확실히 차별화된 포지션.
- **최근 개발 궤적**: 데이터 안전성·성능 하드닝에 집중 (원격 삭제 격리, 충돌 경로 충돌 방지, 핫패스 최적화).
- **핵심 진단**: *"노트를 매우 잘 저장하지만, 사용자가 노트를 찾고·연결하고·다시 방문하도록 돕는 기능은 상대적으로 부족하다."*

## 우선순위 1 — 신뢰 표면(Trust Surface): 저장/동기화/충돌 가시화

앱의 핵심 약속(안전한 로컬 저장 + 폴더 동기화)이 UI에서 전혀 보이지 않는 것이 가장 큰 신뢰 격차.

| 항목 | 근거 | 규모 |
|---|---|---|
| 저장 상태 표시 (저장됨/저장 중/오류) | 상태는 `useAutoSave.ts`에 이미 존재하는데 `StatusBar.tsx`는 카운트만 표시 | 소 |
| 충돌 백업(`.conflicts/`) UI | `.conflicts/`는 기록되지만 `src/i18n.ts`에 관련 문자열이 0개 — 완전한 블랙박스 | 중 |
| 동기화 상태 표시 ("다른 기기에서 수정됨" 등) | 현재 아무 표시 없음 | 중 |
| 토스트/배너 계층 도입 | 현재 오류는 "차단형 네이티브 모달"(`App.tsx:799, 862, 1169`) 아니면 "보이지 않는 crash.log" 둘뿐. 삭제 undo 토스트(`App.tsx:670–698`)와 `aria-live` 영역(`App.tsx:1575`)이 이미 있어 확장 기반은 마련됨 | 중 |

## 우선순위 2 — 빠른 전환기 / 커맨드 팔레트 (Ctrl+P)

- `useKeyboardShortcuts.ts`가 Ctrl+P를 "미래의 quick switcher용"으로 예약만 해 둔 상태.
- 모든 문서가 메모리에 상주하므로 퍼지 매칭 + 한글 초성 매칭은 독립 컴포넌트 하나로 구현 가능. **가치 대비 비용이 가장 좋은 단일 기능.**
- 커맨드 팔레트를 겸하면 단축키 발견성 문제(F8, Ctrl+G 등은 설정 화면을 읽지 않으면 알 수 없음)도 동시에 해결.

## 우선순위 3 — 찾기 옵션 + 접근성 퀵윈 (모두 저비용)

- **대소문자(Aa)/단어 단위 토글**: `SearchHighlight.ts`가 `"gi"` 하드코딩. 특히 Replace All이 의도치 않은 대소문자 변형까지 치환하는 것은 **데이터 변형 버그** 수준 (02번 문서에도 기재).
- **SearchBar/GoToLineBar 접근성**: `SearchBar.tsx:268–303` 모든 버튼이 `tabIndex={-1}`이고 prev/next/close에 `aria-label` 없음 — 가장 명백한 WCAG 위반. ~1시간 작업.
- **Replace All 후 "N개 치환됨" 피드백**: `App.tsx:1575` notice 영역 재사용.
- **`:focus-visible` 아웃라인 복원**: `tiptap-editor.css` 여러 곳(616, 688, 790, 808, 866행)과 `mermaid-theme.css:86–89`, `TitleBar.tsx:153–154`가 대체 표시 없이 제거. `Sidebar.styles.ts:737–744`(2px `colorStrokeFocus2`)가 올바른 패턴이므로 이를 표준화.
- 사이드바 노트 목록에 목록 시맨틱(`role="listbox"/"option"`, `aria-selected`) 부여, 설정 내비게이션에 `aria-current`, 삭제 undo 토스트에 라이브 리전 공지 추가.

## 우선순위 4 — 지식 연결 기능: 백링크 + 태그

Obsidian 대비 가장 큰 기능 격차. "저장된 노트"를 "연결된 지식 베이스"로 바꾸는 축.

- **백링크 패널**: 위키링크가 정방향으로만 해석됨(`WikiLink.ts`). 본문이 이미 메모리에 상주(`attachDocContents`)하므로 역인덱스 비용이 거의 없고, `OutlinePanel.tsx`가 탭(개요/백링크) 형태의 자연스러운 자리.
- **태그(`#tag`)**: 그룹은 배타적·단일 레벨이고 7색 라벨(`noteColors.ts`)은 분류 체계로 확장 불가. `WikiLinkSuggestion.ts`의 자동완성 기계를 그대로 재활용 가능.
- **전역 검색 패널(Ctrl+Shift+F)**: 사이드바 검색은 노트당 스니펫 1개뿐이고 **접근 단축키 자체가 없음**. 최소한 Ctrl+Shift+F로 사이드바 검색 포커스라도 바인딩(퀵윈).

## 우선순위 5 — 첫인상: 웰컴 노트 + 빈 상태(Empty State)

- **첫 실행이 빈 화면**: 온보딩 표면이 `sidebar.empty` 문자열 하나(`Sidebar.tsx:1311`). `/` 명령, `[[` 링크, Mermaid, F8 같은 최고 기능들이 전부 비가시적. → 첫 실행 시 한/영 웰컴 노트 시드가 저장소 내 가장 저렴한 개선.
- **빈 상태 업그레이드**: 사이드바 빈/검색결과없음(`Sidebar.tsx:1311, 1399`), 휴지통 빈 상태(`SettingsModal.tsx:678–681`)가 회색 텍스트 한 줄. 아이콘 + 힌트 + 액션 버튼(새 노트/필터 해제)으로.
- **드래그 규칙 안내**: 검색/색 필터/전체 노트 뷰에서 드래그가 의도적으로 비활성인데 이유를 알려주지 않음 → "필터를 해제하면 순서를 바꿀 수 있어요" 힌트.

## 디자인·비주얼 폴리시

디자인 시스템은 1인 앱치고 이례적으로 규율 있음(모션 토큰 `--motion-*`, 공용 pressable 스타일, FLIP 애니메이션, Mica). 남은 기회:

- **하드코딩 테마 색 정리**: `SettingsModal.tsx:376–391`, `App.tsx:1594–1598` 등이 JS에서 다크/라이트 rgba를 직접 계산 — Fluent 토큰/`--ui-*` 변수 대비 평행 테마 시스템이 자라는 중. 다음 표면 추가 때 다크모드 리그레션 예약 상태.
- **에디터 본문 폭**: `--editor-max-width: 1400px`(`theme.css:102`)는 산문용으로 과도하게 넓음(적정 65–75ch). Typora식 "줄 너비" 설정(좁게/중간/전체) 고려.
- **상태 바 활용**: 저장 상태·동기화 상태·읽기 시간의 자연스러운 자리인데 현재 카운트만 표시.
- **설정 탭 재구성**: "색 필터 유지"(사이드바 동작)가 Display 탭에 있는 등 드리프트 발생(`SettingsModal.tsx:617–623`). "에디터" vs "모양" 탭 분리로 스캔 가능성 회복.
- **상태 바 대비 확인**: 11px `colorNeutralForeground3` on `Background3`(`StatusBar.tsx:33–34`) — 라이트 테마에서 4.5:1 미달 가능성.
