# Project Review — 2026-08-05

Scope: full read of `src/` (hooks, extensions, components, utils), `src-tauri/src/lib.rs`,
build/release workflows, and the maintained docs, against release 0.3.2.

This report has two halves: defects found in the current code, and a product-level
gap analysis. Items marked **fixed in this change** landed together with this
document; everything else is a proposal, not a commitment.

## 1. Standing assessment

The data-safety layer is the strongest part of the project and should be treated as
settled: snapshot/revision guards and per-doc write serialization in `useAutoSave.ts`,
fail-closed atomic body writes, the remote-deletion tombstone lifecycle, the
copy → persist → clear migration ordering with journal-based deferred cleanup, and the
four-step close drain that blocks the window rather than dropping edits. The
supporting quality gates (custom ESLint invariants, grep-based contract tests, FS
fault injection) are what keep it that way.

The weakness is not correctness. It is that the app stores notes very well and does
comparatively little to help a user *find, connect, and revisit* them — and that
several important events (sync conflicts, export progress) never reach the UI at all.

## 2. Defects

### 2.1 PDF export used a fixed temp filename and could never time out — *fixed in this change*

`src-tauri/src/lib.rs` wrote every export to `%TEMP%\noten_print_preview.html`. Two
windows exporting concurrently overwrite each other's HTML, so one PDF can render the
other note's body. `Command::output()` also had no bound: a wedged headless Edge left
the `invoke` pending forever with no UI affordance to cancel or even observe it.

Now: per-invocation temp stem (pid + timestamp + counter), a 90s timeout that kills the
child, stderr captured to a file rather than a pipe (nothing drains a pipe while we
poll, so a chatty child could block and be killed spuriously), and temp cleanup on
every return path — the temp file holds the full note body in plain text.

### 2.2 Find highlights were baked into exported PDFs — *fixed in this change*

`exportAsPdf` serialized `editorEl.innerHTML`, which contains ProseMirror's rendered
decorations, and separately copied every CSS rule in the document — including
`.search-match`. Exporting with the find bar open printed matches in highlighter
yellow. `cloneEditorContentForExport` now unwraps decoration spans on a clone of the
editor DOM before serialization.

### 2.3 Sidebar shortcuts were unreachable by keyboard — *fixed in this change*

`data-sidebar-active` was set from `mousedown` only, so a user who reached the note
list with Tab had F2 / Delete / Ctrl+D / Ctrl+E / Ctrl+Alt+P silently dead (WCAG 2.1.1).
`focusin` now activates the sidebar as well, and focus leaving it deactivates.

### 2.4 Delete acted on a note the user never pointed at — *fixed in this change*

Because activation was sidebar-wide, clicking empty sidebar space and pressing Delete
soft-deleted whichever note happened to be open. The 6s undo toast was the only
safety net. Delete now requires either context-menu routing or a pointer/focus that
landed on an actual note row; the non-destructive shortcuts keep the old, broader
activation.

### 2.5 Startup read every note body with unbounded concurrency — *fixed in this change*

`attachDocContents` issued one Tauri IPC read per note in a single `Promise.all`. On a
few thousand notes in a cloud-synced folder, each read can also trigger placeholder
hydration, so cold start degrades far worse than the file count suggests. Reads now go
through `mapWithConcurrency` (window of 12).

### 2.6 Conflict backups are invisible to the user — open

`.conflicts/` is written correctly, absorbed on load, and carried across directory
migrations — and no string anywhere in `src/i18n.ts` or the UI ever mentions it. Two
PCs editing the same note through OneDrive resolve last-write-wins, and the displaced
version lands in a hidden folder the user has no reason to know exists. This is the
largest trust gap in the product's headline feature and is tracked as a Tier 1 item
below rather than a quick fix, because it needs UI surface (notification + a
"conflicted copies" tab beside Recently Deleted).

### 2.7 Find/Replace is always case-insensitive — open

`findSearchMatches` hardcodes `new RegExp(escaped, "gi")` (`SearchHighlight.ts`). The
comment explains why regex matching replaced index-based folding, which is correct, but
the flag set is not configurable — so **Replace All silently rewrites case variants the
user did not intend** (`id` → `ID` also hits `Id`, `ID`). This is a data-modification
issue, not only a missing feature. Needs `Aa` / whole-word / regex toggles threaded
through `SearchBar` → plugin state.

### 2.8 Status bar "lines" were top-level blocks — *fixed in follow-up*

`StatusBar.tsx` reported `doc.childCount` and `$head.index(0) + 1`, so a ten-item list
counted as one "line" and Ctrl+G navigated by the same unit. `src/utils/documentLines.ts`
now defines a logical line (one per textblock, plus one per newline inside it) shared by
the status bar, its caret row, and Go to Line. Word count was added alongside.

It is still not a byte-exact map of the Markdown file: blank separator lines, list
markers, and table syntax are structure rather than content and stay uncounted. Exact
`.md` line numbers would need a position-preserving serializer.

### 2.9 Duplicate note titles resolved arbitrarily — *partly fixed in follow-up*

Worse than first described: `getTitleMap` took the first match in `docs`, which is the
**sidebar sort order**, so under the default `updated-desc` merely editing one of two
same-titled notes re-pointed every `[[Title]]` at it. `renameNote` then rewrote
`[[Old]]` everywhere, including links that meant the other note.

Now: candidates resolve by `createdAt` (id as tiebreaker), a candidate in the link's own
group wins, click navigation passes a resolved id instead of re-resolving the title, and
`renameNote` skips back-link rewriting entirely when the old title was ambiguous,
reporting the skip so the UI can say so.

Still open: an "ambiguous link" decoration, target information in the link hover
popover, and `[[Group/Title]]` qualifiers. Automatic de-duplication of titles is
deliberately *not* planned — auto-titles change while the first line is being typed, so
a forced suffix would flicker.

### 2.10 Whole-document memory and render cost — *partly addressed in follow-up*

Every note body stays resident (`attachDocContents`) and the sidebar renders all rows.
The flat lists (All Notes, search results, colour filter) — the only views that render
every note, and the only drag-inert ones — now skip off-screen layout and paint via
`content-visibility`, and `scripts/gen-notes.mjs` generates synthetic libraries to
measure against. The re-sort effect no longer builds a whole-library string per commit.

Bodies themselves are still resident. Making them lazy means changing `NoteDoc.content`
to `string | null` so TypeScript forces every consumer to handle the missing case —
`markdownEqual` comparisons and conflict handling silently treating an unloaded body as
empty is exactly the failure this must not have — and it needs a persistent search index
first. That pairs naturally with the global search panel below.

### 2.11 Minor

- `exportHandlers.ts` re-serializes the entire CSSOM (thousands of Fluent atomic rules)
  and re-encodes base64 fonts on every export. Cache the fonts; filter rules to
  `.ProseMirror`.
- `useKeyboardShortcuts.ts` omits `return` after the `Ctrl+O` branch. Harmless today
  because the remaining conditions cannot match, fragile if branches are added.
- The devtools chord invokes `toggle_devtools` in release builds too, where the native
  command is compiled out.
- `docs/architecture.md` advertises "dated review reports" in `docs/`; this file is the
  first one.

## 3. Product gaps

Ranked by value per unit of implementation cost, given what already exists.

### Tier 1 — high value, low cost

| Feature | Rationale | Notes |
| --- | --- | --- |
| Quick switcher (Ctrl+P) | The sidebar is the only way to reach a note; it stops scaling around 50 notes. `Ctrl+P` is already blocked and reserved for exactly this. | Fuzzy match over the in-memory `docs`, Korean initial-consonant (초성) matching, recency ranking. No new persistence. |
| Global search panel (Ctrl+Shift+F) | Sidebar search has no shortcut and shows one snippet per note. | Reuse `stripMarkdownContent` / `extractSnippet`; list every hit with jump-to-position. |
| Conflict + save state surface | See 2.6. | Status-bar indicator (saved / saving / conflict) plus a conflicted-copies tab. |
| Backlinks panel | Wiki links exist but only resolve forward. Every body is already in memory, so the index is nearly free. | Tab alongside the outline panel. |
| ~~Word count~~ (done) | Standard writing metric. | Landed with 2.8; reading time and a detail popover are still open. |
| Find options (Aa / regex) | See 2.7 — correctness as much as convenience. | |

### Tier 2 — differentiators

- **Local version history.** The strongest reassurance a local-first app can offer, and
  the atomic-write plus journal infrastructure already exists. Rolling per-day snapshots
  under `.history/<noteId>/<ts>.md`.
- **Bulk export / backup.** Notes can only be exported one at a time today. Export-all
  covers migration, backup, and sharing at once.
- **Templates and daily notes.** Meeting notes, journals, weekly reviews. Template
  choice on note creation plus a minimal `{{date}}` substitution is enough.
- **Markdown source toggle.** WYSIWYM alone makes fine adjustments to tables, code, and
  links awkward. Round-trip fixtures are already well covered, which lowers the risk.
- **Tags (`#tag`).** Groups are exclusive and single-level; seven color labels do not
  substitute for cross-cutting classification. The wiki-link suggestion machinery is
  directly reusable.
- **Print (Ctrl+P conflict).** Printing is currently blocked with no alternative. If the
  quick switcher takes Ctrl+P, printing needs its own binding and a menu entry.

### Tier 3 — editing detail

Image alt/caption editing (accessibility and Markdown quality; the image context menu
covers only save/copy/replace/delete) · code-block language picker · table column
alignment and CSV paste-to-table · cross-note to-do rollup from existing task lists ·
a welcome note (first run is a blank note, so slash commands, `[[` links, and Mermaid
have almost no discoverability) · archive as distinct from delete · in-group sorting ·
trash search.

### Explicitly not recommended now

- **Tabs / split view.** "One active document per window" is load-bearing for
  `activeDocRef`, the deletion tombstones, and the migration drain. The rework cost is
  disproportionate to the benefit.
- **Note encryption.** Conflicts with both the minimal capability posture and the
  continuous-autosave model. Revisit only with demonstrated demand.
